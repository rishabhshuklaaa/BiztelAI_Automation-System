## 🧠 System Agent Architecture & Responsibilities

### 1. High-Density Ingestion Agent (OCR Core)
- **Responsibility:** Ingests raw multi-part binary image streams via Multer, maps documents to Base64 runtime strings, and extracts multi-row parameters without physical character-recognition drift.
- **Input Object:** Decoded multipart/form-data image buffer streams.
- **Output Object:** Highly structured high-density JSON object carrying a `rows: [...]` data array.

### 2. Real-Time Factory Business Rules Validation Agent
- **Responsibility:** Executes deterministic sanity and logic constraints checks on extracted data matrices inside the lifecycle pipeline loop before persistent database commitments.
- **Target Rules Evaluated:**
  - Mandatory parameters assertion (e.g., Checking for null/empty quantities).
  - Production volume anomalies (e.g., Stripping character placeholders to isolate values).
  - **Cross-Database Audit Sync:** Queries previous MongoDB records to flag **Duplicate Work Order Number Exceptions**.
  - Operational scheduling sequence alignment against absolute uppercase Roman numerals (`I`, `II`, `III`).

### 3. Dynamic UI Review & Confidence Deck Agent
- **Responsibility:** Binds the internal low-confidence character markers (`*`) generated by the inference engine into reactive front-end UI parameters.
- **Applied Tasks:** Dynamically switches input element border configurations to target yellow alerts, appends warning labels natively, and enables immediate state commit cycles for manual human-in-the-loop overrides.

## 💡 Prompt Engineering & Debugging Interventions

During the development lifecycle, standard LLM outputs caused string processing crashes due to markdown envelope injection (e.g., wrapping responses inside ` ```json ... ``` ` strings). 

### The AI-Native Optimization (Designed via ChatGPT & Gemini loops):
We eliminated manual regex parsing blocks on the API routing layer by configuring strict `response_format: { type: 'json_object' }` variables natively inside the Groq endpoint options, achieving 100% stable schema parsing.

## ⚖️ Development Tradeoffs & Philosophy

- **Prioritized Protocols:** High execution speed, automated workflow loops, practical high-contrast usability, and deterministic exception handling.
- **Deprioritized Layers:** Premature architectural microservice decoupling, excessive layout polish, and hyper-complex bounding-box coordinate tracking.
